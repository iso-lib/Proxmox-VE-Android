# Proxmox-VE-Android

> 本プロジェクトは上流の [5p00kyy/Proxmox-VE-Mobile](https://github.com/5p00kyy/Proxmox-VE-Mobile) を起点として、独立した新規プロジェクトとしてリポジトリを立て直したものであり、もはやその上流の fork ではありません。上流のコードを基に、本プロジェクトには次のものが含まれています：10 言語への翻訳（英語、ドイツ語、スペイン語、簡体字中国語、フランス語、イタリア語、ポルトガル語、ロシア語、日本語、韓国語）とログイン画面での言語切り替え、折りたたみ可能な一覧カード・コンパクトなシステム状態カード・横並びのクイックアクション・整理された VM／LXC 詳細アクションなどの UI 改善、LXC ゲスト（xterm.js）と VM ゲスト（noVNC）向けの軽量 WebView ゲストコンソール、ダーク／ライトテーマ・更新間隔・自動ログイン・問題報告など実際に動作する設定、GitHub Releases で配布される正式署名済みの安定版 1.0.0（今後はバージョンタグのプッシュで自動リリース）、そして Proxmox VE Android への改名。

`Proxmox VE Android` は、スマートフォンやタブレットから Proxmox VE 環境を閲覧・操作するための Android クライアントです。

現在の安定版（1.0.0）は、一般的なモバイル運用ワークフローに焦点を当てています。ログイン、安全な接続処理、ダッシュボードの可視性、ノードの移動、VM/LXC のライフサイクル操作、タスクの追跡、および読み取り専用のインフラ検査です。単一モジュールの Kotlin/Jetpack Compose アプリであり、画面が所有する Retrofit 呼び出しから、リポジトリを基盤とした機能スライスへ移行しつつあります。この README は、目指す最終状態ではなく、現時点のリポジトリの姿を説明するものです。

## 1.0.0 の新機能

最初のベータ版と比べて、1.0.0 は最初の安定版です：[1.0.0](https://github.com/iso-lib/Proxmox-VE-Android/releases/tag/v1.0.0)。

- **最初の安定版。** バージョン 1.0.0（versionCode 4）、GitHub Releases で配布され、プロジェクトのリリース鍵で署名されています。今後はバージョンタグ（`v*`）をプッシュすると自動的にリリースされます。
- **ゲストコンソール。** LXC ゲスト（xterm.js）と VM ゲスト（noVNC）向けの軽量 WebView コンソールで、Proxmox 標準のコンソールページを読み込みます。パスワードセッションはセッションチケット Cookie で認証します。
- **実際に動作する設定。** ダーク／ライトテーマ、ダッシュボード・VM・コンテナ・タスク一覧の 10〜60 秒の更新間隔、保存済み認証情報での自動ログイン、GitHub Issues への問題報告リンク。生体認証と通知のスイッチは実装のないプレースホルダだったため削除されました。
- **ローカライゼーション。** アプリは 10 言語に翻訳されています：英語、ドイツ語、スペイン語、簡体字中国語、フランス語、イタリア語、ポルトガル語、ロシア語、日本語、韓国語。この README は 7 言語で提供されています。
- **インターフェースの改善。** 折りたたみ可能な一覧カード、コンパクトなシステム状態カード（CPU、使用中／合計メモリ、稼働時間）、横並びのクイックアクション、ログイン画面の言語切り替え、整理された VM／LXC 詳細アクション。
- **ログインと TLS。** ホスト／IP 入力の HTTPS 正規化、自己署名証明書の初回利用時の信頼フローと SHA-256 フィンガープリントのピンニング、パスワードまたは API トークンでのログイン。
- **新しい名前。** Proxmox VE Mobile から Proxmox VE Android に改名しました：アプリ名、設定画面のヘッダー、バージョン情報ダイアログ。

- リポジトリを基盤とした機能 ViewModel によるタスク履歴の読み込み。ノード選択、ステータス/種類/VMID フィルター、詳細/ステータス、タスクログ表示、実行中タスクの停止リクエストを含みます。

- 読み込み、エラー、再試行、更新、キャッシュされたノード選択を備えた、リポジトリを基盤とした機能 ViewModel によるネットワークインターフェース一覧。

## アーキテクチャ

このプロジェクトは、厳密に層化されているというよりは、現在軽量な構成です。

- `presentation/`：Compose 画面、ナビゲーション、`MainViewModel`
- `data/api/`：Retrofit API 定義と認証/クライアント設定
- `data/model/`：API モデル
- `data/security/`：暗号化された認証情報ストレージと認証情報ストアのコントラクト
- `data/session/`：現在の認証セッションの所有権とセッションサービスのコントラクト
- `presentation/auth/`：認証 UI 状態/セッションコントローラー
- `data/dashboard/`、`data/node/`、`data/vm/`、`data/lxc/`、`data/task/`、`data/network/`、`data/storage/`、`data/user/`、`data/backup/`、`data/cluster/`：最初のリポジトリを基盤とした垂直スライス

アプリはリポジトリを基盤とした機能スライスへ移行しつつあります。ダッシュボード、ノード詳細、VM 一覧/詳細、LXC 一覧/詳細、タスク、ネットワーク、ストレージ、ユーザー、バックアップ、クラスタステータスは、専用のリポジトリと機能 ViewModel を使うようになりました。VM 詳細には、リポジトリ経由で読み取り専用の設定とスナップショットデータが含まれるようになりました。認証状態/API サービスへのアクセスは `AuthSessionController` の背後にあり、保存されたログインデータは `CredentialStore` の背後にあり、`MainViewModel` は引き続きキャッシュされたノードと全体的なダイアログの関心事を所有しています。ノード詳細では、VM、LXC、ストレージ、ネットワーク、タスクの各ビューを開く際にノードの識別情報が保持されるようになりました。

## セキュリティに関する注意

- パスワード認証情報と API トークンの断片は、暗号化された shared preferences に保存できます。
- HTTPS はデフォルトでプラットフォームの TLS 検証を使います。
- 自己署名 HTTPS サーバーでは、Android に信頼されたインポート済み CA、またはピン留めした SHA-256 証明書フィンガープリントを使うことができます。
- SSL 検証を無効にできるのは、信頼できるラボサーバー向けのデバッグビルドのみです。リリースビルドでは、プラットフォームの TLS 検証または設定済みの SHA-256 証明書フィンガープリントが必要です。
- リリースビルドでは、アプリ全体のクリアテキスト通信はもう要求されません。デバッグビルドでは、ローカルテスト用に HTTP が引き続き許可されます。
- 推奨される `openssl` コマンドと初回利用時信頼（trust-on-first-use）ポリシーの注意点については、[`SECURITY.md`](SECURITY.md) を参照してください。

## プライバシーに関する注意

- アプリにはテレメトリやアナリティクスは含まれていません。
- 保存されたホスト詳細、ユーザー名、パスワード、API トークン ID、API トークンシークレットは、認証情報の保存が有効な場合、暗号化された shared preferences を通じてローカルに保存されます。
- アプリは、設定された Proxmox VE エンドポイント以外に認証情報を意図的に送信しません。
- バグ報告では、パスワード、API トークン、チケット、Cookie、CSRF トークン、秘密鍵、共有すべきでない公開 IP の詳細、機密性の高いホスト名を除去してください。

## 既知の不足点

- 自動テストのカバレッジは狭く、現在はセッション/認証、ダッシュボード、ノード、VM、LXC、タスク、ネットワーク、ストレージ、ユーザー、バックアップ、セキュリティ、ローカライゼーションの接合部に集中しています。
- CI はビルド、lint、単体テストのために存在します。
- いくつかの依存関係や UI の一部は、放棄された、または未完成の機能開発を示唆しています。
- 一部の設定は、実行時の動作が実装されるまで計画段階または無効のままです。

## 推奨される次のステップ

1. 実際の Android SDK/エミュレーターでアプリを検証し、Proxmox インスタンスに対して実際に成功する画面/操作を記録します。
2. 実際の Proxmox アプライアンスとリバースプロキシに対して、自己署名証明書のガイダンスを検証します。
3. `v0.1.0-beta.1` のスモークマトリックスを実行し、タグ付け前にベータ版のブロッカーのみを修正します。
4. QA 証拠が集まったら、変更履歴を `Unreleased` から `v0.1.0-beta.1` へ昇格させます。
5. 延期されたパリティ作業を、焦点を絞ったベータ後のリリーストレインへ引き続き移していきます。

具体的な段階的ロードマップについては、[`docs/revival-plan.md`](docs/revival-plan.md) を参照してください。より広い製品、リファクタリング、QA、ワークフロー、コミュニティの開発サイクルについては、[`docs/development-cycle-2026.md`](docs/development-cycle-2026.md) を参照してください。最初の公式ベータ版のチェックリストについては、[`docs/beta-release-plan.md`](docs/beta-release-plan.md) を参照してください。
